一、创联（2024.12–2026.08）

1. 一体化考试平台（iep-web）

规模：Vue3 + TypeScript + Element Plus + Vite + Pinia + UnoCSS。366 个 ts 文件、47 个组件目录、我的提交 131 次。[源码]

亮点 1：列表、查询、编辑三块都是配置驱动

列表 YTable（493 行）：columns 数组描述列，children 递归做多级表头；列支持 slot 插槽、render(h) 函数、show 条件显示、fixed/sortable/sortMethod/align/minWidth。内置分页用 defineModel('pageNo'/'pageSize') 双向绑定，configFlag 控多选/序号/展开行/边框；可选 dragRow 用 sortablejs 拖拽排序；表头右键弹「导出为 excel」（eltable-as-xlsx，可配排除列，3 秒后自动关）；autoHeight 按视口算高度。

查询区 YForm（556 行）：searchForm 数组支持 13 种字段类型（Input、InputNumber、InputPwd、Textarea、Select、Cascader、Radio、RadioButton、Checkbox、Date、Daterange、Time、DateTime、Datetimerange），也能直接给任意 slot；isShow 做字段联动（数组看长度、其他看真假）；超过 3 个字段自动折叠，展开/收起时 dispatchEvent(new Event('resize')) 让表格重算高度；search() 把空串转 null、pageNo 重置为 1、pageSize 保留，配了 formConfig.rules 才走校验。

编辑表单 Form：schema 驱动的独立组件（TSX + componentMap + 栅格），和 YForm 不是一回事——YForm 只管查询区。

所以一个业务模块 = index.vue + config.ts + api。config.ts 里 searchForm() 是工厂函数（把字典选项传进去），columns 里用 h() 写渲染，字典翻译、时间格式化都在配置里做。阅卷计划页就是这么用的：config.searchForm({ EXAM_PLAN_TYPE_NEW: getIntDictOptions(...) })。

怎么讲：这套东西不是为考试平台新写的，是育龄平台 commonTable 那套思路带过来的，到这边做成了三个通用组件。

这套封装的问题和改法（面试可直接说）

被问"这套封装有什么不足"或"如果重写你怎么改"时，挑两三条说，不用全倒。

  1. 表格高度是全局找元素算的。 autoHeight 里用 document.querySelector('.y-table')，一页放两个表格就测错，resize 监听也没解绑。重写的话让组件接一个容器 ref，或者用 ResizeObserver 只盯自己这块，卸载时断开。

  2. 斑马纹关不掉。 :stripe="configFlag.stripe || true" 恒为 true。重写把默认值放进 props 的 default，不要用 || 兜底。

  3. 类型声明是假的。 type: Number || String 实际恒等于 Number。重写用 [Number, String]。

  4. get-table-ref 拿不到东西。 在 setup 阶段就 emit，外面收到的永远是 null。重写改成 onMounted 之后再 emit，或者直接用 defineExpose。

  5. YForm.reset() 把字段全置 null，不是回默认值。 所以阅卷计划页要手动把 gradingStatus 改回 1。重写让组件记一份初始值快照，reset 时还原，并且只清查询字段。

  6. validate() 没暴露、getFormRef 也是 null。 重写统一走 defineExpose({ validate, reset, clear })，父组件要用什么就暴露什么。

  7. "展开筛选"按钮只在挂载后算一次。 窗口 resize 后不重算，该隐藏的时候还显示。重写监听 resize 或用 ResizeObserver 重算。

  8. 权限指令没有 updated。 v-hasPermi 只在挂载时执行一次，权限变了不会重算。重写补 updated 钩子，或者用响应式判断包一层。

  9. 翻页里留了 console.log。 重写接 ESLint 的 no-console，别靠自觉。

封装思想（面试问"讲讲你的组件化"时，两分钟版）

这套东西解决的不是"表格怎么封"，是"列表页怎么批量生产"。后台的列表页其实都是同一个形态——上面查询、中间按钮、下面表格加页码。我把这个形态固定成组件，页面里只剩三样：columns、searchForm、接口。用起来很直接：查询区写一个数组，表格写一个 columns，分页 v-model 绑上 pageNo/pageSize，请求挂两个事件就完了。阅卷计划页一共 233 行，一行 el-table-column 都没写，列全在 154 行的 config 里，加新页面基本就是照抄一份配置改字段。

三个组件不在一个抽象层次上。YForm、YTable 是约定式组件，配置给的是参数——"这列叫什么、多宽、能不能排序"；Form 是 schema 渲染器，配置给的是元数据——"这个字段用什么组件、怎么校验"，由 componentMap 解释执行。查询区形态稳定，用约定就够了；编辑表单字段千变万化，才需要解释器。

关键在逃生口。columns 有 slot 和 render(h)，YForm 有 item.slot 和自定义按钮，配置吃不下就退回手写。很多自研配置化表格死在"多一个特殊列就加一个配置项"上，最后成了半成品低代码，我们没往那条路走。

它也有代价：跨组件靠隐式副作用——搜索时自动改 pageNo、折叠时 dispatch resize 让表格重算高度，效率高，但读代码看不出来；全局 querySelector 找表格、resize 监听不解绑，都是这个思路的副作用。如果重写，第一件事是把这些隐式协作换成显式的接口约定。

三十秒版（对方随口一问时用）

简单说，就是把"列表页"做成模板：页面只填列配置、查询项和接口，表格结构一行不用写，分页、空态、折叠组件自带；配置吃不下就留插槽手写，不硬堆配置项做成低代码。代价是组件间靠隐式副作用通信，重写会先换成显式接口。

亮点 2：阅卷主链路，题型组件动态渲染

views/grading 拆成 plan（计划）、record（记录）、task（任务）、gradingPaper（阅卷卷面）。阅卷卷面 topic.vue 用 <component :is> + 题型码映射到六种题目组件（单选、多选、填空、简答、案例、组合），支持仲裁标记、主观题打分。题型配置集中在 QUESTION_CONFIG，加题型只改映射。

怎么讲：阅卷这块难点不在页面，在状态——从计划到成绩中间环节多，我先把状态图理出来再对着接口字段一个个对。

亮点 3：试卷水印

hooks/web/useWatermark.ts：canvas 画 300×240 的平铺水印，旋转约 30 度、rgba(0,0,0,0.15)、pointer-events: none、z-index 置顶；窗口 resize 时重建，组件卸载时 clear() 移除节点和监听。

怎么讲：防不住专业截图，作用是追溯和威慑，这点跟产品说过。

亮点 4：导出 PDF

utils/htmlToPDF.ts：html2canvas + jsPDF。先按 190×277 的纸面比例算出每页像素高度，再逐个检查元素有没有跨页，跨页就在节点后面插一个空白占位块，避免表格行被切断；渲染倍率 1.3。

配套踩坑：富文本里的 <br> 导出后换行乱、标签漏出来，导出前要洗一遍内容。[提交 2025-07-08]

亮点 5：权限和字典

permission.ts：白名单 + token 判断 + 后端下发菜单 generateRoutes() 后逐个 addRoute，跳转带 redirect 参数还原（含 query 解析）；字典用 Pinia 全局拉一次、缓存进 sessionStorage，避免每个页面都拉。

怎么讲：字典预加载和动态路由是两件最容易被忽略、但直接决定后台好不好用的事。

业务覆盖面：阅卷、监考中心（考试监控列表）、监管中心（评价机构、机构列表）、考试计划、成绩（人脸记录、成绩审核）、证书 PDF 导出。[提交]

5. 联合国官网（lhg）

规模：pnpm monorepo，packages/ 下 entry、pc-app、mobile-app、shared 四个包；Vue3 + TS + Element Plus。我的提交 20 次。[源码]

亮点 1：从 0 搭 PC 站

布局组件、首页、关于我们、详情页、移动端留资弹窗，都是这个项目里从零写的。[提交 2025-08-21~08-28]

亮点 2：钉钉签名（这个最值得讲）

问题：生产环境钉钉接口缺 sign，通知发不出去。根因是 Web Crypto API 只在安全上下文（HTTPS/localhost）可用，生产走 HTTP 时算不出 HMAC-SHA256。方案：shared/utils/dingtalk.ts 里优先用原生 API，不可用时回退 crypto-js，纯前端解决，不用后端加接口。排查过程写成了 DINGTALK_SIGN_SOLUTION.md。[源码+文档]

亮点 3：Monorepo 与部署

pnpm workspace 管依赖，shared 包放公共工具；Rainbond 部署配置、Dockerfile、server.js（SPA 托管）、deploy.config.js 都在仓库里；TS 自动导入、项目引用的问题也都记了文档。[源码]

亮点 4：图片加载优化

单独做了懒加载验证页和优化。[提交 2025-09-02]

二、瀚维（2020.11–2022.07）

1. 成都市育龄妇女健康数据管理平台（fertileWoman-new）

规模：Vue2 + Element UI，23 家妇幼保健机构、500 多个基层机构。[简历+源码]

亮点 1：配置化表格（这是你配置化思路的起点）

components/table/commonTable.vue：config 控制多选列、序号列、斑马纹、边框、默认排序、表头样式、行样式、最大高度；列配置支持 prop/label/width/自定义渲染；留了 prepend 插槽给表头附加内容。页面里基本只剩配置和接口。

亮点 2：业务选择器组件化

MyCol（栅格列）、SelectWomen（育龄妇女选择）、CascaderOrgan（机构级联）、CascaderOther、CascaderDown——把反复出现的"选人、选机构"做成组件，不用每个页面写一遍。

亮点 3：表格/图表自适应

Mixins/resize.js：debounce(100) 监听窗口 resize，兼顾侧边栏折叠的 transitionend；用 keep-alive 时在 activated/deactivated 里重新绑定/解绑，避免缓存页面监听失效。这就是"4:3 屏也能用"的实现底子。

亮点 4：模块自动引入

api/index.js、store/index.js、icons/index.js 都用 require.context 扫目录自动注册，加模块不用改入口文件。

注意：一键部署脚本在 webapp 那个项目里（见下），这个项目只有 build/index.js 的预览脚本，别把两件事说混。

4. 爱维产品导航（productnav）

规模：Vue3 + Vue CLI 5 beta + Vuex4 + Sass，80 个文件、6.1 MB。[源码]

亮点 1：两屏翻屏

Home.vue 用 wheel 事件切屏，.first/.second 两个 class 配 transition: all 1s，顶部固定 2.5rem。

亮点 2：数据大屏

5 个模块，接口 GET /bacc/sysmanager/projectGuide，字段覆盖总人数、省/市/县数量、乳腺和宫颈的筛查量、检出、治疗指标；页面里 window.g.ApiUrl 配接口域名。

4 个板块、10 个产品、25 个跳转链接；星云产品有 7 个子模块浮层（数据管理、在线预约、现场登记、过程管理、排号大屏、报告查询、决策分析）。

亮点 4：手写 canvas 进度环

ProgressBar.vue 用 canvas 画环，配 10 张环形精灵图做流光；props 接受 type/len/percent/color/text，没引图表库。

可以主动说的坑（加分项）

现在回头看有几处问题：宫颈那块标题复制成了"乳腺筛查量"、检出率用错了字段、rem 只在 mounted 算了一次、wheel 监听没移除。这些是我后来做 code review 才意识到的——讲出来比藏着强。

三、这些亮点怎么连成一条线

同一条思路，两个阶段：

育龄平台的 commonTable 是"配置化"的起点（2021），到创联的 YTable/YForm + config.ts 变成了体系（2025）。同一条线讲下来，能说明你不是每次从零开始，而是把上一个项目的东西带过去继续改。

复杂业务：

考试平台的阅卷链路（计划→任务→卷面→成绩），题型组件动态渲染、水印、PDF 导出，三件事各有一个技术点，够讲十分钟。

工程化：

联合国官网的 monorepo（4 个包）+ 钉钉签名回退 + Rainbond 部署，是"从 0 到上线"的完整证据链。

多端：

职证宝（uni-app，小程序+H5）、志愿者（原生小程序 + 后台）、爱维星云（H5），三种形态都碰过。
